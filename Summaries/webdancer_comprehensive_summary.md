# WebDancer: Towards Autonomous Information Seeking Agency

**Authors:** Jialong Wu, Baixuan Li, Runnan Fang, Wenbiao Yin, Liwen Zhang, Zhengwei Tao, Dingchu Zhang, Zekun Xi, Gang Fu, Yong Jiang, Pengjun Xie, Fei Huang, and Jingren Zhou  
**Affiliation:** Tongyi Lab, Alibaba Group  
**Paper version supplied:** arXiv:2505.22648v3, dated August 10, 2025

## 1. Background and Context

Web agents are systems that perceive the live web, reason about a task, choose actions, use tools, and adapt to the resulting observations. Systems such as Deep Research and Grok DeepSearch demonstrate the potential of autonomous agents to conduct long, multi-step information searches.

The paper divides earlier information-seeking agents into two broad groups:

- Prompt-driven systems that instruct a large language model (LLM) or large reasoning model (LRM) to perform complex searches without additional training.
- Systems that train search or browser use through supervised fine-tuning (SFT), reinforcement learning (RL), or both.

The authors identify several shortcomings in prior work:

- Training-free prompting does not fully exploit the reasoning abilities of reasoning-specialized models.
- Existing trained agents often use relatively easy data. Some datasets, such as 2Wiki, already have performance above 80%.
- Many questions require only one search or a few steps rather than sustained investigation.
- Challenging benchmarks are too small for effective training: GAIA has 466 examples, WebWalkerQA 680, and BrowseComp 1,266.
- SFT and off-policy RL can generalize poorly in complex live-web settings.
- Starting directly with on-policy RL in a multi-tool environment may spend early training mainly on learning tool-format compliance rather than higher-level agency.

The central challenge is therefore not merely attaching search to an LLM. A useful autonomous web agent needs:

1. Diverse, fine-grained browsing data reflecting different user goals and interaction contexts.
2. Reliable long-horizon trajectories supporting task decomposition and multi-step reasoning.
3. Scalable training that generalizes to changing websites, unfamiliar interaction patterns, and long-term goals.

The authors use **ReAct** as their organizing framework. ReAct alternates reasoning with actions and observations: the model thinks about what to do, invokes a tool, reads the result, and repeats until it can answer.

## 2. Research Goal and Objectives

The goal is to give open-source models autonomous, multi-turn information-seeking abilities and to provide a reproducible path for building a Deep Research-like web agent from scratch.

The proposed WebDancer pipeline has four stages:

1. Construct diverse, difficult web question-answer pairs.
2. Sample reliable tool-using trajectories with both ordinary LLMs and reasoning-specialized models.
3. Use SFT as a cold start so the model learns the ReAct interaction pattern.
4. Apply on-policy RL to improve decision-making, extended reasoning, tool use, and generalization.

The experiments ask whether this complete data-and-training pipeline:

- Improves different model sizes and both LLM and LRM backbones.
- Beats untrained “vanilla” ReAct and non-agentic retrieval methods.
- Generalizes to difficult English and Chinese browsing benchmarks.
- Benefits from synthetic datasets, filtering, SFT initialization, and subsequent RL.
- Reveals practical lessons about reasoning length, consistency, data efficiency, and instability in live web environments.

## 3. Methods (Approach/Design)

### 3.1 Overall design

WebDancer is an end-to-end technical training study rather than a human-participant experiment. It synthesizes question-answer data, generates and filters ReAct trajectories, trains web agents, and evaluates them on live information-seeking benchmarks.

The agent ultimately cycles through:

`Thought → Action → Observation → Thought → … → Answer`

The available action names are `search`, `visit`, and `answer`, meaning that there are two external information-seeking tools plus the terminating answer action.

- `search` accepts a query and an optional year filter. Its observation contains the top 10 titles and snippets.
- `visit` accepts a URL and an information goal. Its observation is an evidence-and-summary response generated by a summarizer model.
- `answer` ends the trajectory.

The summarizer is Qwen-2.5-72B. The system is implemented on Qwen-Agents.

### 3.2 Synthetic QA construction

The authors collected **60,000 CRAWLQA** questions and **40,000 E2HQA** questions.

#### CRAWLQA

CRAWLQA starts with root URLs from official or knowledge-rich sites, including arXiv, GitHub, and wiki-style sources. The pipeline recursively follows hyperlinks to collect progressively deeper pages. GPT-4o then generates questions from this material using prompted question types such as:

- Counting
- Multi-hop reasoning
- Intersection questions

**Figure 1** illustrates this process as a browsing tree. A root site leads to subpages and deeper descendants; accumulated content is passed to GPT-4o to create a question-answer pair. Its example asks which game ranked fourth in the February 2025 Godot XR Game Jam but did not appear in the 2024 Godot Games showreel; the answer is “Keziah’s House.”

#### E2HQA

E2HQA converts easy, entity-focused SimpleQA-style questions into harder multi-hop questions without changing their answers.

At iteration \(n\):

1. Select an entity \(E_n\) from the current question \(Q_n\).
2. Search for new content \(C_n\) concerning that entity.
3. Ask an LLM policy to turn the retrieved content into a replacement query \(R_n\).
4. Substitute \(R_n\) for the entity, yielding a harder question \(Q_{n+1}\).

The paper summarizes the replacement as \(R_n=\pi(S(C_n))\), meaning that the LLM rewrites content returned by search into a new subproblem. Each rewrite forces the solver to answer an additional subproblem before reaching the unchanged original answer. Difficulty can therefore be controlled through the number of rewriting iterations.

Figure 1’s example evolves the direct question “Who received the IEEE Frank Rosenblatt Award in 2010?” into an indirect question describing the award and the recipient’s work. The final answer remains “Michio Sugeno.”

### 3.3 ReAct trajectory sampling

A trajectory history consists of all preceding thoughts, actions, and observations. At each step, the policy conditions on this history to generate the next thought and action.

The authors generate two kinds of reasoning supervision:

- **Short-CoT:** GPT-4o directly executes ReAct and produces relatively concise thoughts.
- **Long-CoT:** QwQ-Plus receives the historical actions and observations and independently decides each next action. Previous thoughts are withheld from its next-step input because it was not trained on multi-step thought histories, but each newly generated reasoning segment is retained as supervision.

Each QA instance is rejection-sampled up to **five times**.

The appendix’s prompts show two variants:

- **Figure 6, ordinary LLM prompt:** requires interleaved thought, action, action input, and observation; asks the model to assess whether its evidence chain is complete, explain tool selection, and provide a final answer only when confident.
- **Figure 7, LRM prompt:** uses a reduced action-oriented format, requires complete JSON parameters, and explicitly tells the model to gather evidence with tools before answering.

### 3.4 Three-stage trajectory filtering

Generated trajectories pass through a funnel:

1. **Validity control:** discard outputs that fail to follow ReAct formatting, especially under long contexts.
2. **Correctness verification:** retain only correct answers, judged by GPT-4o according to the cited evaluation procedure.
3. **Quality assessment:** apply rules and prompting to remove hallucination, severe repetition, redundant information, goal misalignment, and illogical or inaccurate reasoning.

The paper’s wording says the rule-based stage filters trajectories “with more than two actions,” although this statement is difficult to reconcile with Table 4’s mean short-CoT action count of 4.56; no clarification is provided.

Repetition filtering constrains the maximum occurrence of any 10-gram to four times per trajectory. Questions whose trajectories are rejected remain useful as RL prompts.

### 3.5 Supervised fine-tuning

SFT teaches the model to alternate reasoning, tool calls, observations, and final answers:

- Thoughts: `<think>…</think>`
- Actions: `<tool_call>…</tool_call>`
- Observations: `<tool_response>…</tool_response>`
- Final answers: `<answer>…</answer>`

**Figure 2** shows a base model being fine-tuned on reformatted CRAWLQA and E2HQA trajectories. After cold-start training, the SFT model becomes the policy used for RL rollouts.

Observation tokens are excluded from the SFT loss. In plain terms, the model learns to produce its own thoughts and actions but is not trained to predict externally returned search results. The loss is the average negative log probability of all non-observation tokens.

The training dataset contains:

| CoT type | Trajectories | Mean action count | Mean thought length |
|---|---:|---:|---:|
| Short | 7,678 | 4.56 | 510.03 tokens |
| Long | 6,550 | 2.31 | 1,599.39 tokens |

Qwen-2.5-7B and Qwen-2.5-32B use Short-CoT data. QwQ-32B uses Long-CoT data.

### 3.6 Reinforcement learning

WebDancer uses **Decoupled Clip and Dynamic Sampling Policy Optimization (DAPO)**, an on-policy RL method. For each QA pair, it samples a group of candidate trajectories, computes their rewards and normalized advantages, and adjusts the policy toward higher-reward generations while clipping overly large updates.

Important details include:

- Only model-generated tokens are optimized; tool responses remain context but are excluded from the optimized output.
- Dynamic sampling removes prompt groups for which every rollout is correct or every rollout is wrong.
- This filtering is particularly useful because automatically synthesized QA pairs may be noisy or invalid.
- The RL rollout group size is **16**.
- The RL stage can reuse QA pairs that never produced acceptable SFT trajectories.

The reward is:

- 10% format correctness
- 90% answer correctness

Both components are binary. Format receives 1 only when the full response follows the required structure and every JSON tool call is valid. Answer correctness receives 1 only when the judge model deems the response correct. The final reward is therefore:

\[
0.1\times\text{format score}+0.9\times\text{answer score}.
\]

The judge is based on Qwen-72B-Instruct.

Figure 2 depicts RL as repeated policy rollouts containing reasoning and tool calls, followed by a reference-model/KL component, reward calculation, group computation, advantage estimation, and policy updating.

### 3.7 Benchmarks, evaluation, and implementation

Primary evaluation uses:

- **103 questions** from GAIA’s text-only validation split.
- **680 questions** from the WebWalkerQA test set.

Both are evaluated with LLM-as-judge and Pass@1. Additional tests use:

- BrowseComp in English.
- BrowseComp-zh in Chinese.
- Pass@1 and Pass@3, depending on the reported benchmark result.

The baselines cover:

- Non-agentic base models and retrieval-augmented generation.
- OpenAI Deep Research.
- Search-o1, R1-Searcher, WebThinker, and SimpleDeepSearcher.
- Vanilla ReAct using the same backbones.

Inference settings are temperature 0.6 and top-p 0.95. Repetition penalty is 1.1 for LRMs and 1.0 for ordinary LLMs. RL rollouts use temperature 1.0 and top-p 1.0. Training used **32 nodes**, each with **eight NVIDIA H20 96-GB GPUs**.

### 4.4 SFT and RL effects

Training QwQ with RL alone, without the SFT cold start, produced only **5% Pass@3 on GAIA**. This demonstrates that multi-step, multi-tool instruction following must first be established through supervised trajectories.

**Figure 4** compares SFT and RL across three model scales using Pass@1, Pass@3, and Cons@3. The exact labels show RL gains of:

| Model | Pass@1 gain | Pass@3 gain | Cons@3 gain |
|---|---:|---:|---:|
| Qwen-7B | +7.70 | +2.90 | +2.67 |
| Qwen-32B | +5.80 | +5.80 | +8.68 |
| QwQ-32B | +1.95 | +0.97 | +1.74 |

The chart’s underlying bar values are not printed precisely enough for reliable transcription, but the annotated differences are clear.

For ordinary, non-reasoning Qwen models, RL delivers substantial improvements, particularly Qwen-32B’s 8.68-point consistency gain. For QwQ, all improvements are small. The authors suggest that excessively long LRM trajectories produce sparse rewards and that further on-policy optimization may consequently have limited benefit.

They also observe that post-RL Pass@1 can approach the SFT baseline’s Pass@3, suggesting that RL makes correct answers easier to obtain in a single attempt.

The upward trend supports continued improvement with more RL steps over the measured range.

### 4.6 Emergent reasoning and action behavior

**Figure 5(b)** compares the base, SFT, and RL Qwen-32B models. Approximate plotted trends are:

- Action count increases from about 3.5 for the base model to about 6.1 after SFT and around 6.3 after RL.
- Reasoning length increases from about 375 tokens to about 420 after SFT and approximately 480 after RL.

Exact numerical labels are absent, so these readings are approximate. The authors’ central conclusion is that SFT induces more tool actions and longer reasoning, while RL extends reasoning further and helps produce more sophisticated decision sequences, intermediate subgoals, and autonomous tool choices.

### 4.7 Temperature, instability, and memorization

**Figure 5(c)** tests decoding temperatures 0.5, 0.6, and 0.7. Pass@1 and Pass@3 change only slightly; Pass@3 remains in the low 40s and Pass@1 roughly in the low-to-mid 30s. Exact values are not printed.

The small temperature effect suggests that output sampling variability is not the primary cause of unstable agent performance. The authors instead attribute much of the fluctuation to the live web itself, which is:

- Non-stationary.
- Open-ended.
- Partially observable.
- Subject to changing pages and contexts.

In a memorization stress test, Qwen-7B was fine-tuned on **69 correctly sampled GAIA development trajectories for 10 epochs** and evaluated on the same examples. Greedy decoding achieved only **37.4%**, despite direct exposure to the evaluation trajectories. This illustrates how difficult it is to stabilize behavior in open-domain tool-using tasks and argues against explaining the observed performance simply as memorization.

### 4.8 Case study

**Figure 8** follows WebDancer on a GAIA question asking for the ZIP code where the fish popularized by *Finding Nemo* was recorded by the USGS as a nonnative species before 2020.

The trajectory demonstrates:

1. **Decomposition:** identify the fish, locate the USGS record, then convert the location to a ZIP code.
2. **Hypothesis formation:** infer that Nemo is the clown anemonefish, *Amphiprion ocellaris*.
3. **Hypothesis testing:** search the USGS nonindigenous species database.
4. **Evidence retrieval:** find a July 2018 occurrence at Fred Howard Park, Pinellas County, Florida.
5. **Information-gap recognition:** notice that the USGS record lacks a ZIP code.
6. **Iterative correction:** perform another search for Fred Howard Park’s address.
7. **Answer:** return **34689**.

One thought segment in the displayed trajectory unexpectedly discusses chinstrap penguins, which is unrelated to the actual query. The subsequent trajectory returns to the correct task and produces the checked answer. This visual therefore demonstrates both adaptive tool use and the possibility of stray or inconsistent reasoning content.

## 5. Analysis and Interpretation

The results answer the paper’s central question affirmatively: an open-source web agent can acquire stronger autonomous search behavior through coordinated data construction, trajectory filtering, SFT, and on-policy RL.

The authors draw several broader lessons:

- **Agency is necessary.** Base models and simple RAG perform badly on tasks requiring active navigation, evidence collection, and decision-making.
- **Strong reasoning backbones help.** QwQ-32B produces the strongest open WebDancer results, particularly when trained on Long-CoT supervision.
- **Training improves even a lightweight framework.** WebDancer consistently beats vanilla ReAct without requiring an elaborate hand-engineered multi-agent workflow.
- **Trajectory quality outweighs raw volume.** The filtered 6,550-example dataset beats larger unfiltered configurations in Figure 3.
- **SFT and RL serve different functions.** SFT teaches basic interaction structure and provides the necessary cold start; RL then improves decision quality, consistency, reasoning length, and adaptive action selection.
- **RL benefits ordinary LLMs more than an already strong LRM.** Qwen models obtain meaningful gains, while QwQ improves only marginally, possibly because long trajectories make binary reward signals sparse.
- **Reasoning traces do not transfer cleanly across model classes.** Long-CoT from a strong reasoning model particularly benefits another reasoning model, but creates high invalidity and repetition in instruction-tuned models.
- **Agent evaluation is inherently noisy.** Multiple attempts and Cons@3 reveal aspects of reliability that Pass@1 alone misses.
- **The live web prevents easy stabilization.** Temperature changes have little effect, while even aggressive memorization training does not ensure that an agent repeats previously successful behavior.
- **RL produces behavioral changes, not just higher answer scores.** Trained agents reason longer, use more actions, and increasingly select intermediate subgoals and tools autonomously.

Relative to related systems, WebDancer differs in using a native ReAct sequence in which an action occurs after its corresponding reasoning step. WebThinker also uses SFT followed by RL but employs off-policy RL and embeds actions and observations inside its thinking representation. SimpleDeepSearcher relies only on SFT. WebDancer instead combines trajectory SFT with on-policy DAPO and is designed to support both instruction LLMs and LRMs.

## 6. Contributions and Novelty

The paper’s main contributions are:

- A systematic four-stage recipe for building an end-to-end information-seeking agent from scratch.
- Two scalable synthetic QA strategies:
  - CRAWLQA, based on recursively explored web pages.
  - E2HQA, which transforms simple entity questions into controllably harder multi-hop questions without changing their answers.
- A method for obtaining both Short-CoT and Long-CoT ReAct supervision from different model types.
- A three-stage rejection-sampling and filtering process covering format validity, correctness, and reasoning quality.
- A two-stage learning design in which SFT establishes native ReAct behavior and on-policy DAPO improves generalization.
- A way to reuse rejected or unsampled SFT questions during RL rather than discarding them entirely.
- Evidence across GAIA, WebWalkerQA, BrowseComp, and BrowseComp-zh that the approach improves multiple backbones and generalizes across English and Chinese information-seeking tasks.
- Detailed empirical findings on data quality, cold-start requirements, RL benefits, reasoning-transfer brittleness, consistency, and instability in dynamic web environments.
- An open-source-oriented alternative to systems based primarily on closed foundation models and complex prompt engineering.

## 7. Limitations and Caveats

The authors identify the following limitations:

- **Only two external tools:** search and page visiting are insufficient for more advanced browser interaction.
- **Narrow task type:** the main experiments concern short-answer information-seeking. The system is not evaluated on document-scale research and long-form writing.
- **Limited RL data use:** although the authors collected 100,000 QA pairs, RL can use only a small subset—about **5,000 pairs**—because of computational and stability constraints.
- **High rollout cost:** every RL sample requires several model completions and tool invocations, which slows training and experimentation.
- **One reasoning style per model:** current models train on either Short-CoT or Long-CoT rather than dynamically adjusting how much they reason.
- **Tool hallucination:** a model can try to invoke unavailable tools, such as a nonexistent calculator.
- **Over-action:** an agent may continue searching or acting after it has already confirmed the answer.
- **Long-CoT brittleness:** it creates high invalid rates and repetitive output, especially in smaller instruction models.
- **Limited gains for LRMs:** QwQ obtains only small improvements from RL, potentially because very long trajectories receive sparse outcome feedback.
- **Dynamic-environment instability:** live websites change and provide partial information, making exact reproducibility and stable behavior difficult.
- **Small, variable primary evaluation set:** detailed GAIA analysis uses only 103 text-only validation questions.
- **LLM-based evaluation:** answer correctness, trajectory filtering, and rewards depend on model judges rather than deterministic verification.
- **Binary rewards:** the reward provides little partial credit or fine-grained guidance.
- **Benchmark gap:** even WebDancer’s absolute BrowseComp scores remain low, and OpenAI Deep Research remains far ahead on GAIA.
- **Internal presentation inconsistency:** the claim that trajectories with more than two actions are filtered is not reconciled with a reported average of 4.56 actions for Short-CoT data.
- **Case-study reasoning noise:** Figure 8 includes an unrelated chinstrap-penguin thought, showing that a correct final answer can coexist with internally inconsistent reasoning.
- **Missing reports:** several comparison-table cells are marked unreproducible or unreported, limiting complete comparisons.

The broader-impact discussion also warns that autonomous web agents could propagate misinformation if they trust unreliable sources or be misused for automated content extraction and surveillance. The authors call for transparency, source attribution, and responsible deployment.

## 8. Future Work or Open Questions

The paper proposes or motivates the following next steps:

- Add richer modular browser tools and model more browser functions directly.
- Incorporate a Python sandbox for external API interaction.
- Extend beyond short answers to document-level research and long-form generation.
- Develop more informative and reliable reward models for open-ended writing.
- Improve RL stability and sample efficiency so the full synthetic corpus can be exploited.
- Reduce the cost and latency of interleaving model completions with external tool calls.
- Scale the filtered dataset and test whether more high-quality data continues to improve performance.
- Build hybrid reasoning agents that dynamically choose short or long reasoning depending on the task.
- Reduce hallucinated tool calls, repetition, and unnecessary actions.
- Improve robustness to changing web content and partial observability.
- Investigate why on-policy RL saturates quickly for reasoning-specialized models.
- Find more reliable ways to transfer reasoning patterns from strong reasoners to smaller instruction models.

## 9. High-Level Takeaway (Plain Language)

WebDancer teaches a language model how to conduct a web investigation rather than merely giving it a search result. The researchers automatically create difficult questions, collect examples showing how to think and use search tools, teach that behavior with supervised learning, and then refine it with reinforcement learning. This consistently makes several open models better than their untrained ReAct versions, with the strongest WebDancer reaching 51.5 Pass@1 and 64.1% Pass@3 on GAIA. The work also shows that clean training trajectories and a supervised cold start are essential, while live-web agents remain expensive, unstable, and far from solving the hardest browsing tasks reliably.
